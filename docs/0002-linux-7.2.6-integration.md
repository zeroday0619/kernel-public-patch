# Linux 7.2.6 local integration series

This series reproduces the changes applied to the local Linux 7.2.6 source:
BORE 6.8.0, acpi_call, selected Clang DKMS warning adjustments, distribution
metadata, the Charcoal port, and video configuration/workload tools. It affects
81 paths and preserves source contents and executable flags.

Artifacts are in
[`patches/0002-linux-7.2.6-integration/`](../patches/0002-linux-7.2.6-integration/).
Step 4 includes metadata behavior adapted to this Linux 7.2.6 target. Do not
apply the separate root-level legacy metadata patch on top of this series.

## Base and compatibility

The base is the captured local pre-patch source, whose Makefile identifies
Linux **7.2.6**. It already contains distribution-specific changes, including
POC 2.6.3 and ADIOS 3.3.0. It is not pristine upstream Linux 7.2.6. The source
snapshot had no usable Git history, so an upstream base commit cannot be
assigned reliably.

`base-files.sha256` and `base-modes.json` describe the affected existing files.
`new-files.txt` lists paths that must not exist before application. These
records establish exact touched-file preimages, not the identity of every
untouched dependency. Start from the same source distribution and snapshot;
matching the version string or forcing patch context is insufficient.

## Apply to a compatible source

Use `git apply`, which preserves executable flags for the new shell tools.
This is a source integration series, not a `git am`-ready upstream submission.
The commands below assume a clean compatible Git checkout and stop on failure:

```bash
set -e
patch_directory=/absolute/path/to/kernel-public-patch/patches/0002-linux-7.2.6-integration

test -z "$(git status --porcelain)"
(cd "$patch_directory" && sha256sum -c SHA256SUMS)
sha256sum -c "$patch_directory/base-files.sha256"
while IFS= read -r path; do
    test ! -e "$path" || exit 1
done < "$patch_directory/new-files.txt"

while IFS= read -r patch_file; do
    whitespace=error-all
    if [ "$patch_file" = 0001-bore-6.8.0.patch ]; then
        whitespace=warn
    fi
    git apply --check --index --whitespace="$whitespace" \
        "$patch_directory/$patch_file"
    git apply --index --whitespace="$whitespace" \
        "$patch_directory/$patch_file"
done < "$patch_directory/series"

sha256sum -c "$patch_directory/result-files.sha256"
```

The BORE input contains four whitespace diagnostics in `kernel/Kconfig.hz`
help text: three whitespace-only lines and one space-before-tab indentation.
They remain unchanged to reproduce the applied source exactly. `warn` reports
them without rewriting bytes; no context or whitespace matching is relaxed.
All other steps passed `--whitespace=error-all`. A strict full-tree whitespace
check can still report those inherited BORE lines.

For reversal, use a disposable copy or first verify that affected files still
match `result-files.sha256`. Apply the six patches in reverse order with
`git apply --reverse --index`, checking each before applying. Preserve any
later edits rather than forcing reversal. No rollback is performed by simply
copying this repository.

## Video tools

After applying the series, the kernel tree contains:

- `kernel/configs/video-common.config` and the interactive/throughput fragments.
- `tools/video/configure.sh`, `run.sh`, `benchmark.sh`, and a Makefile.
- `tools/video/README.md`, `VALIDATION.md`, and shell regression tests.

From that kernel tree:

```bash
make -C tools/video check
make -C tools/video configure BASE=/path/to/hardware.config PROFILE=interactive
make -C tools/video configure BASE=/path/to/hardware.config PROFILE=throughput
tools/video/run.sh --dry-run interactive -- ffmpeg -version
```

Interactive configuration uses full preemption and 1000 Hz; throughput uses
lazy preemption and 250 Hz. Configuration runs use separate output directories
and compile only Kconfig host utilities. They preserve the explicit baseline's
hardware, compiler, and signing choices and verify requested symbols. Provide
the referenced signing certificates before a kernel build. Generated `.config`
files, hardware snapshots, build outputs, and temporary backups are not shipped
in this public repository.

Execution profiles use transient user scopes and verified CPU weights, with
optional process affinity, memory protection, and delegated I/O weighting.
They do not switch the running kernel. Kernel-version-specific and runtime
limitations are documented with the tools.

## Verification and remaining work

The [series validation record](0002-linux-7.2.6-integration/series-validation.txt)
records indexed reverse and forward checks. All six steps were reversed and
reapplied in an isolated reconstruction. All 81 final files matched the applied
workspace byte-for-byte and retained their executable flags. Reversal restored
the recorded preimages and removed every added file.

Prior implementation checks included the video tool regressions, both Kconfig
profiles, and real user-scope CPU/memory/affinity read-back on the then-running
older kernel. The Charcoal source port's checkpatch result had zero errors and
34 reviewed warnings; normalization for packaging does not turn those checks
into compilation or hardware tests. Detailed historical subsystem reviews are
linked from the porting table.

A follow-up Clang qualifier fix was verified by compiling `mm/vmscan.o`
with LLVM 22 and Full LTO. Its constant sysctl limit now uses the existing
explicit `void *` conversion pattern; bounds and warning policy are unchanged.

Complete kernel images and modules have not been built, installed, or booted
as part of this work. Memory-pressure/data-integrity tests, swapoff/hot-remove, legacy
32/64-bit futex client compatibility, GPU and Wi-Fi behavior, and video/gaming
performance remain **Verification required**. NAP and Polly are optional;
source inclusion does not imply activation. Existing explicit configuration
choices can also keep ADIOS and multi-compressor zram disabled.

AI-assisted adaptations require human review and validation before deployment
or submission. Original license and attribution records are preserved, and no
new human sign-off is asserted.
